# Kids clothing pivot

Approved strategy: clothing only, ages 2–12. Garment categories are Tops, Bottoms, Dresses & Jumpsuits, Sets & Outfits, Knitwear & Outerwear, Sleepwear, Underwear & Socks. Audience (girls/boys/unisex), age bands (2–4/5–8/9–12), exact supplier size, colour, price and stock are facets, not duplicate categories. Unisex appears in both audience destinations. New In and Sale are dynamic destinations. Only populated garment categories appear in navigation.

Medusa contract: add GET /store/clothing-products accepting existing product query fields plus audience= girls|boys, age=2-4|5-8|9-12, size, colour, availability=in_stock, price=u1000|1000-5000|o5000, sale=true, sort=featured|newest|price_asc|price_desc. Return {products,count,offset,limit,facets:{sizes:string[],colours:string[]}}. Apply filters and sorting before pagination, and match size/colour/age/stock on the same variant. Selecting age, size or colour means an available fit: those facets require a purchasable matching variant even when the separate stock checkbox is off. Unfiltered detail retains sold-out eligible sizes. Keep existing Medusa product/cart/customer endpoints. Product metadata.clothing={audience: girls|boys|unisex, material?, care?, fit?}; variant metadata.clothing={age_min:number,age_max:number,height_min_cm?,height_max_cm?}; options named Size and Colour preserve supplier labels. Explicit garment-category allowlist plus clothing metadata restrict discovery. GET /store/clothing-products/:id for published eligible detail (404 for retired/non-clothing); include categories/options/variants metadata/prices/inventory. GET /store/clothing-categories returns populated category tree in Medusa category response shape. Invalid filters return 400.

Migration: idempotent category setup and retire non-clothing by draft status, never delete products/orders. Default dry run with reviewed apply flag; only run against isolated local test database in this task. Existing clothing requires explicit metadata/size mapping; never infer real measurements. Dedicated local fixture seed creates clearly labelled QA garments; production seed must no longer recreate baby/maternity products. Cart add/update/complete must reject newly retired products without blocking line removal or historical order access. Storefront removes unavailable saved favourites from display and identifies retired cart items for removal.

UI: retain established visual language; replace baby copy/navigation with kids clothing, Girls/Boys and age destinations. Garment sidebar and exact size/colour filters use new backend contract. Clothing cards lead to explicit size choice rather than arbitrary quick add. PDP size guide states age is guidance, shows only supplied measurement data, material/fit/care when known. Cart/checkout/order items show selected variant. Legacy compatible handles map to new garment types; unrelated old category URLs display retired-department explanation with Shop clothing link.

Non-goals: manufacture commercial assortment, supplier sizing, photography, legal policy changes, payment-provider redesign or production deployment. Previously found payment and free-shipping problems remain recorded release gates.
